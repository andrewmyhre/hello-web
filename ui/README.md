# hello-web UI

A SvelteKit PWA for the hello-web API, built with the static adapter as a
single-page app. It signs in through the API's Google flow, shows the
signed-in user's avatar and name, and has a side menu with a Home link.

It is served on the same origin as the API: the dev ingress sends `/auth`,
`/me`, `/health` and `/openapi.json` to the API and everything else to this
app (`deploy/dev/ingress.yaml`). The session cookie is HttpOnly, so the app
never sees it; it asks `GET /me` who is signed in.

## Shared UI package

The account menu, avatar, side menu, user badge, the API helpers (`getMe`,
`signOut`) and the service worker policy are not in this project. They come
from `@andrewmyhre/web-base-ui`, which `package.json` pins by the URL of a
tarball on a go-web-base GitHub release (`ui/vX.Y.Z`). Do not edit them here:
fix them in go-web-base's `packages/web-base-ui`. A new version arrives when
you run `uvx copier@9.19.1 update`, which moves the URL and the lockfile.

What stays here is yours: routes, `+layout.svelte`, `app.html`, `app.css`
(the components use global class names such as `.account-menu` and `.avatar`
and are styled there), the manifest, the generated client and the service
worker entry. See the package's README for its exports.

## The API client is generated

`src/lib/api/openapi.d.ts` is generated by `openapi-typescript` from
`openapi.json`, and `openapi.json` is what the Go code serves at
`GET /openapi.json`. Neither is edited by hand. After changing the API:

```sh
pnpm run generate   # go run ./cmd/hello-web openapi > ui/openapi.json, then openapi-typescript
```

Two checks keep them honest:

- `TestCommittedOpenAPISpecIsCurrent` (Go, `cmd/hello-web`) fails when
  `openapi.json` differs byte for byte from what the code renders.
- `pnpm run check:client` (the `ui` pipeline step) regenerates the client into
  `.client-check/` and fails on any difference from the committed file.

Requests go through `openapi-fetch`, typed by the generated `paths`:
`src/lib/api/index.ts` exports `api = createApiClient<paths>()` from the shared
package, which also fails type checking if the OpenAPI document loses
`GET /me` or `POST /auth/logout`.

## Service worker

`src/service-worker.ts` precaches the build and `static/`, serves those from
the cache, and answers navigations from the network with the cached shell as
the offline fallback. It never handles the API's paths (`/auth/*`, `/me`,
`/health`, `/openapi.json`), as a fetch or a navigation, so nothing about a
session is ever cached. The rule is `@andrewmyhre/web-base-ui/sw-policy`, tested in the package.
A new API path prefix must be added to `EXTRA_API_PREFIXES` in
`src/service-worker.ts` and to the ingress.

## Development

Node 20.19 or later, and pnpm through corepack (`packageManager` pins it).

```sh
pnpm install
pnpm dev        # proxies the API paths to http://localhost:8080
pnpm test       # vitest
pnpm check      # svelte-check, warnings fail
pnpm build      # static site in build/
```

Google sign-in works locally only with an API whose redirect URI is
`http://localhost:8080/auth/google/callback`, so local sign-in lands on the
API's port rather than the dev server's.

## Image

`deploy/ui.Dockerfile` builds the site and serves it with
nginx-unprivileged (`deploy/ui-nginx.conf`, SPA fallback to `index.html`).
